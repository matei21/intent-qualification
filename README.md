# Company Qualifier

A company search system that takes a natural-language query and returns ranked, relevant companies from a corpus of around 450 records. An LLM extracts structured filters from the query, then hybrid vector search and scoring surface the best matches.

The frontend includes a world-map data explorer for filters and null values and an LLM-powered intent search. See the [demo video](https://drive.google.com/file/d/1q7Lr8Q0_e1ck59jvtfUZpSJRqfMnHX8O/view?usp=drive_link) or run locally with the steps below.

## Quick start

**Prerequisites:** Python 3.10+, Node 18+, Docker, and an API key for any OpenAI-compatible provider.

**1. Start Qdrant**
```bash
docker-compose up -d
```

**2. Install backend dependencies**
```bash
cd backend
pip install -r requirements.txt
```

**3. Create `backend/.env`**
```
# Any OpenAI-compatible provider — Groq, OpenAI, Together, Mistral, Ollama, …
LLM_API_KEY=your_key_here
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=meta-llama/llama-4-scout-17b-16e-instruct

# OpenAI example:
# LLM_API_KEY=sk-...
# LLM_BASE_URL=https://api.openai.com/v1
# LLM_MODEL=gpt-4o-mini

# Local Ollama example:
# LLM_API_KEY=ollama
# LLM_BASE_URL=http://localhost:11434/v1
# LLM_MODEL=llama3

# Optional — enables Langfuse tracing
# LANGFUSE_PUBLIC_KEY=...
# LANGFUSE_SECRET_KEY=...
```

**4. Preprocess (one-time, around 10–15 min first run)**
```bash
python preprocess.py
```
Downloads BGE-M3, extracts KeyBERT keyphrases, generates hybrid embeddings, indexes into Qdrant.

**5. Start the backend**
```bash
uvicorn main:app --port 8000
```

**6. Start the frontend**
```bash
cd frontend
npm install
npm run dev
```

Open [http://localhost:5173](http://localhost:5173)

## How it works

Each query goes through four stages:

1. **LLM filter extraction** — one API call converts the free-text query into `structured_filters` (country, revenue, employees, year, NAICS codes, business models, target markets) and a `semantic_query` noun phrase.
2. **Hard filtering** — a pandas boolean mask applies exact/range predicates. Null values pass through (a company with no recorded revenue is not excluded by a revenue filter), but a frontend tag warns the user that the result lacks some values, as they're null.
3. **Hybrid dense retrieval** — BGE-M3 encodes the semantic query (generated by the LLM) into a 1024-dimensional dense vector + sparse lexical weights. Qdrant searches `core_offerings` and `description` collections. A categorical safety net pulls the top-10 dense candidates unconditionally so strong semantic matches aren't silently dropped.
4. **Scoring and gating** — `total = 0.50 × cosine(core_offerings) + 0.50 × cosine(description)`. Two gates apply: a NAICS-bypass rule (no NAICS match requires `max(core, desc) ≥ 0.60`) and a score floor (`total ≥ 0.50`). An optional cross-encoder reranker (BGE-reranker-v2-m3) can re-score the surviving pool.

## Stack

- **LLM** — any OpenAI-compatible provider (default: Groq / llama-4-scout-17b)
- **Embeddings** — BAAI/bge-m3 (dense + sparse hybrid)
- **Keyword extraction for description of the company** — KeyBERT (all-MiniLM-L6-v2)
- **Vector DB** — Qdrant (Docker)
- **Reranker** — BAAI/bge-reranker-v2-m3 (optional, CPU)
- **Backend** — FastAPI
- **Frontend** — React + Vite + react-simple-maps
- **Observability** — Langfuse (optional)
